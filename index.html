about

Pipelines as production software

I'm a data engineer at Play'n GO, where I built and manage the commercial and games data domains on AWS: batch pipelines from business systems, streaming pipelines from Kafka, the SQL data models and datasets built on them, and the governance around it all.

Before that I spent five years in DevOps at Scania and at Ericsson through AFRY, working with CI/CD, infrastructure as code and monitoring. That background is why my pipelines are versioned, deployed automatically, monitored, and built from reusable parts rather than one-off scripts.

Lately I've been working on the layer between governed data and the people and tools that use it: a semantic and context layer that gives AI agents the business definitions and context they need, and the agents that use it.

What I work on

in production

Data platforms on AWS

I built and manage the commercial and games data domains in a data mesh.

  • Pipelines for Dynamics 365 CRM, Freshdesk and Freshchat, including incremental loads based on update timestamps
  • Kafka pipelines that receive financial events and raise alerts
  • Medallion architecture with star and snowflake schema models, SCDs and Athena views
  • Cross-account sharing with Lake Formation
  • A generator for Glue scripts and CloudFormation templates
building

Semantic and context layer

The business definitions and context AI agents need to answer correctly.

  • Metric definitions based on the Apache Ossie standard
  • Business context alongside the definitions, for agents
  • Proof of concept first, tested with SQL and an agent
building

AI agents

Agents that answer from governed data instead of guessing.

  • Built and deployed on Amazon Bedrock and Bedrock AgentCore
  • Local agents in VS Code for engineering tasks
  • Grounded in the semantic and context layer
